# CONTEXT.md: shared vocabulary

Domain and architecture terms used across Entieve. Domain canon lives in
`docs/lore/` (UNIVERSE, FACTIONS, AESTHETIC, NAMING: binding); this file
names the *modules and seams* we build that vocabulary into.

## Domain (the world)

| Term | Meaning |
|---|---|
| **Corporation** | a named manufacturing house (`corp-*`, `content.AllCorps`): the maker of a hull, module or charge, carrying a display name and an emblem; a supplier layer, never a power bloc |
| **Hull** | a ship chassis (`ship-*`); flyable or machine |
| **Hull portrait** | side-view full-colour art of a hull, nose to the right (`uikit/hulls`): a flat SVG source in `svg/` rasterized at build time to committed 120/240 px PNGs, keyed by hull id (`Get`/`Has`); a drop-in at `assets/hulls/<id>.png` wins and is mip-sampled for the box it fills. Three surfaces draw it as a **wide block** with the art contained (never cropped): the HUD status panel and the fitting window's identity block are the same **4:1 240×60** frame, the Show Info hull page's hero is **2:1 200×100**. The fitting window's other zones are unchanged. The world grid never draws it: an in-space ship is a **class icon** |
| **Class icon** | what the world grid draws for a ship instead of its portrait: one flat, upright, **non-rotating** glyph per hull class (`render.classGlyph`, procedural polygons in `render/art.go`), so the silhouette names the class and the tint names the affiliation through the bracket rule (`bracketColor`: player cyan, hostile red, neutral orange). Every hull of a class shares the glyph; the afterburner is a halo, not a directed flame |
| **Module** | a fitted component (`mod-*`); slot-classed high/mid/low |
| **Mount** | a hull's high slot, declared as a kind and a size (`high_mounts`); a mounted module needs a mount of its own kind at or above its size, so a large gun never sits on a frigate |
| **Turret mount / launcher mount** | the two mount kinds: guns and the mining laser are turret-mounted, rockets and missiles launcher-mounted |
| **Grid class / cpu class** | a module's powergrid or cpu demand as one of three classes (Class I / Class II / Class III), never a number; a module demanding both axes consumes one unit on each |
| **Class quota** | a hull's per-class allowance on each axis (`grid_classes` / `cpu_classes`); a fit is legal while no class's module count exceeds its quota, which is what bounds a full rack |
| **Item** | everything else tradeable: ore, mineral, charge, round, loot (`ore-*`/`min-*`/`ammo-*`/`charge-*`/`loot-*`) |
| **Tradeable** | any marketable id (item, module or hull) resolved through one ladder (`widgets.ResolveTradeable`, item → module → hull, the sim's `itemName` order): kind, display name and themed icon (drop-in art wins), or the raw id with no icon and no ref when no def backs it |
| **Round family** | a round size class **and** gun family as one `ammo_class`: `small-autocannon`, `small-artillery`, `medium-autocannon`, `medium-artillery`, `large-autocannon`, `large-artillery`. One family is one calibre: every round of it has the same m³ volume, and only guns of that family load it (autocannon = rounds, artillery = shells) |
| **Round** | the ammunition item (`ammo-*`) a projectile gun loads: its family + one of the four damage profiles; the gun's `damage_multiplier` is its share of the round's volley (autocannon light and fast, artillery heavy and slow) |
| **Bay** (clip) | a charge-consuming module's fixed m³ ammunition space (`weapon.bay_m3`, `boost.bay_m3` for the cap booster): whole rounds of exactly one round type, sized so sustained fire reloads about every 120 s |
| **Load cycle** | filling a bay from cargo: a full bay's rounds, taking exactly one firing cycle (no capacitor cost), so the next shot is deferred by it. The rounds move in at the start; the bay is ready when the cycle completes (the rack draws the ring lit meanwhile and a shell marker once armed). `CmdSetAmmo` starts one; the swarm's bays get their single granted type at boot (no UI to show a cycle yet) |
| **Standing order** (`ModuleRuntime.Selection`) | the round type `CmdSetAmmo` picked: the **only** thing a player's bay loads. It survives an empty bay and a stock-out (it reloads that type when it is back), and with no order the bay loads nothing, however much cargo fits it |
| **Waiting state** | a bay sitting empty with no standing order while rounds that fit sit in cargo: the gun logs one `<module> waiting for ammo selection` line, deactivates quietly, and fires only once `CmdSetAmmo` picks a type. Distinct from truly dry (empty bay, no rounds of the order in cargo = the `no charges` warning). NPC bays are the one exception: with one granted type they load it themselves |
| **Caste** | an Old Works machine archetype (`npc-*`: Scuttler, Marauder, Hierarch) + the Charter patrol (Kuštor) |
| **Station** | a market/service node (a celestial); stations hold the order books |
| **Service** | a station's offered capability, owned by one table (`content.Services`): the id content files spell, its display label and icon, and the Screen window that id unlocks (`repair` opens none). The dock strip no longer draws a button per service (the rail owns every window), so the table is the vocabulary the Screen rows are gated on (through **Station access**, never the raw list) |
| **Station access** | the one answer to "may the player use this service HERE": docked, the station offers it, and it still runs it (a **remnant** keeps market, repair and refinery and darkens industry and fitting). `sim.ServiceAvailable` is the composition the refusing gate `stationAccess` applies, without its log, forwarded by `ContentView.ServiceAvailable`; every surface gates on it and none re-derives the rule: the rail's `Service` entries, fitting's Fit/Unefit/Assemble, the market's trade verbs, the order window and the inventory's Sell. the seam's `StationInfo` carries the docked-at identity alone (`Name`, `System`): what a station HAS lives in the sim's station component, what the player can USE is `ServiceAvailable`, and no screen reads a second service list |
| **Order book** | per-station continuous double auction: sell orders + buy orders, never-crossed |
| **Market tree** | the market window's browse hierarchy, built from every marketable def's `group` path (`Ships/Frigates`, `Modules/High/Turrets`, `Materials/Ore`, …): `All` at the root, a branch click scopes the catalog, and the search field filters the selected branch by name, path and maker |
| **Buy order** | a standing buy on a station book (the sim's *bid*, `sim.OrderBuy`): buy at your price or better, resting until filled or cancelled. The player-facing word everywhere; code identifiers keep `bid` |
| **Sell order** | a standing sell on a station book (the sim's *ask*, `sim.OrderSell`): sell at your price or better, resting until filled or cancelled. The player-facing word everywhere; code identifiers keep `ask` |
| **Open order** | a player's standing buy or sell order resting on a book: up to 20 universe-wide, partial fills accumulate, cancelled by id (3% broker fee charged at placement and kept on cancel; 2.5% sales tax on executed sells) |
| **Quote** | the one read that prices an amount (`sim.Quote`, forwarded by `ContentView.Market().Quote`): given a station's book, an item, an order side and a quantity, the **executed walk** of each resting order's price and the units it fills, best price first (ascending asks for a buy, descending bids for a sell), with the remainder priced at the last price when the depth runs short, plus the broker fee (buy) and the sales tax (sell) over the units the book actually fills, from the same `marketFees` the commands charge. Components, never one blended number: legs, walk, executed value, units filled, fee, tax and the depth-short and priced flags, so a surface composes the figure it shows. `CheapestAsk` is its sibling read on the same handle (the cheapest sell order any market station rests), and the screens hold no walk of their own: the **Quantity picker**'s preview is the composed wallet move, and the **Profit table** and **Refine math** take the walk alone |
| **Recipe** | two-tier manufacturing: minerals → products (`rec-*`) |
| **Job** | one manufacturing run queue at any station (industry); all stations share three global job slots |
| **Manufacturing** | the industry window (key B): the **Recipe board** (browse tree, recipe list, **Recipe inspector**) over the job list in the bottom seam, the three global slots, and the **quantity picker** on Start (runs 1–100) whose Confirm starts the job; the job list keeps Collect/Cancel. Renamed from Factory; its layout sidecar key is `manufacturing` (old `factory` files migrate on read) |
| **Recipe board** | the manufacturing window's browse | recipes | inspector row (`uikit/screens/manufacturing.go`), the market window's own idiom (its browse column is the same code, `panes.go`) over the recipe products' `group` paths: the tree scopes the list to a branch (`All` is the whole catalog) and the search field filters that branch live over the product name, its family and **its inputs** (a mineral query finds every recipe that eats it); a row click opens the recipe in the **Recipe inspector** and highlights its branch back. Three named seams persist in the layout sidecar (`manufacturing-jobs` the board over the job strip, `manufacturing-tree` and `manufacturing-inspector` its row) |
| **Recipe row** | one recipe in the board's list as a rich row: the product icon (the market list's item icon size) and the product name with its **Recipe verdict** glyph on line 1, the per-run time and the **Cost strip** on line 2 (no fee: it lives in the **Recipe inspector** and its **Profit table**) |
| **Recipe verdict** | a recipe's one-glance start state as one glyph and nothing else: `✓` (Good) when Start would accept, `×` (Danger) when it would refuse. The shape carries the state (not colour alone, WCAG 1.4.1); the greyed Start and the **Material bill**'s Danger rows say the rest. The sim's own `CanStartJob` is the authority |
| **Profit table** | the **Recipe inspector**'s one-run cost math as aligned label/value rows (`widgets.PlainTable`), priced off the docked station's **order book** (never a content base price): Materials (the **Quote** read on the bill's asks, the walk's spend, the tail at the last sell order when the depth runs short; a line with no local sell order takes the cheapest sell order any other market station rests, marked `†` and explained in the table's footnote, and one with no sell order anywhere is left out of the total and named there), Craft fee (the sim's `JobFee`, unchanged), Total cost, Sale price (the **Quote** read on the product's bids over the output qty, the tail at the last buy order, dashed `— · no buy order` when the local book holds none), Profit and Margin. The figures move only when the book's priced rows move; Profit is signed and tinted Good at break-even or better, Danger below it |
| **Cost strip** | a recipe row's one-bar cost make-up: a segment per mineral in canonical mineral-id order (so a row never shuffles between frames, recipes or authored input order), each width its share of the run's material value (base price × committed need) split to whole pixels by `widgets.ShareWidths`, tinted `Good` while the stock covers that mineral and `Danger` where it is short. A share strip, never a chart (the brief's D4 flow diagram stays unbuilt) |
| **Recipe inspector** | the selected recipe's card in the board's right pane, inset by `ContentsPad`: it leads with the **Item head** (the market's own: hero icon, the product's name carrying the **Recipe verdict** glyph, its wrapped description), then the **Profit table**, the **Material bill** (one row per mineral, the cost driver first, the mineral art at three times the inline icon) and the **RESULT** section (one row per output: the product's art and name over the units one run actually makes, `×100` for a batch of ammunition or charges and `×1` for a module or a hull, dashed when a recipe declares no qty) sharing one scroll viewport with the **Scroll gutter**'s rail, and **Start job** pinned below it (greyed, no hint line, when the sim would refuse). No craft-level summary and no per-run time/fee/value line: the craft time is the recipe row's, the money is the profit table's. Rebuilt only when the bill, the station, the slots, the pane's width or the priced book rows move |
| **Material bill** | one run's committed need per mineral (the sim's craft-discounted `JobMaterials`) beside the player's have side and the mineral's value weight, in canonical mineral-id order: the numbers StartJob takes, what the **Cost strip** splits and what the **Recipe inspector** lists by value, each row leading with the mineral's art at 48 px (three times the inline row icon) and sharing its two-line row shape with the **RESULT** section's rows |
| **Job fee** | 3% of a recipe's mineral value at base prices, per run, debited from the wallet at job start; kept on cancel |
| **Refinery** | the ore→mineral window at a `refine` station, read the manufacturing board's way in three panes: a **Market tree** over the ore groups with a live search (over the ore's name, its group and the minerals it yields, so "sideron" finds every ore that produces it), the **Ore row** list (every stack in the cargo and the ore hold, canonical ore order), and the **Refinery inspector** for the selected ore. Its notched **Quantity picker** opens on the inspector's **Refine** button (100/200/300…, capped at the stock; under 100 ore nothing refines and the button is grayed), never on the row click; the minerals always land in the station hangar, never the ship's hold, so a full hold never blocks a refine |
| **Ore row** | one held ore in the refinery's list rich row: the ore icon at the market list's item size and the ore's name with its **Ore verdict** glyph on line 1, the held count and the **Yield strip** on line 2. The cells are only the fit source; the row's only declared interaction is Show Info (Refine is the inspector's button) |
| **Ore verdict** | an ore's one-glance refine state, one glyph and nothing else: `✓` (Good) when the docked station runs a refinery and the holds cover one whole batch, `×` (Danger) when either fails. Same shared glyph as the **Recipe verdict**, and like it the greyed button and the panel's numbers say the rest: no hint line names the reason |
| **Yield strip** | an ore row's one-bar value make-up: one segment per output mineral in canonical mineral-id order, each width the mineral's share of one batch's mineral value (base price × `floor(refine_yield × 100)`), split to whole pixels by `widgets.ShareWidths`, tinted from the stat-family ramp so adjacent segments read apart (outputs carry no have/need state for the **Cost strip**'s Good/Danger to say). Basis: base prices, the manufacturing cost strip's survivor |
| **Yield bill** | one whole batch of the selected ore in the **Refinery inspector**: one row per output mineral, the most valuable first, each leading the mineral's art at the material bill's 48 px box, its share of the batch's mineral value on line 1 and the sim's `floor(refine_yield × 100)` amount beside its base-price value on line 2. No have/need bar: a batch's outputs are not a commitment |
| **Refine math** | the **Refinery inspector**'s money table, the profit table's sibling answering "refine this or sell it raw": **Ore value** (what one batch of 100 ore fetches at the docked book's bids, the **Quote** walk), **Minerals value** (every output mineral's proceeds at the bids, the same read), **Refine delta** (minerals − ore, Good at 0 or above, Danger below) and **Margin** (delta / minerals). No fee row: the sim charges none. A side the book holds no buy order for dashes `— · no buy order` and the two derived lines dash with it; no content base price stands in. The table quotes one whole batch whatever the stock holds, like the profit table quotes one run |
| **Refinery inspector** | the selected ore's card in the refinery's right pane, inset by `ContentsPad`: the **Item head** (hero icon, the ore's name carrying its **Ore verdict**, its wrapped description; the head's hint alone while nothing is selected), then **Refine math** under the PROFIT bar and the **Yield bill** under "YIELD · most value first", both in one scroll column with the house rail, and **Refine** pinned below (grayed by the ore's own gate, no hint line). Rebuilt only when the selection, the station gate, the holds, the pane's width, the priced book rows or the batch's own output quantities move |
| **Craft level** | a station's learned skill per product family (grows with volume) |
| **Proficiency** | a pilot's learned right to run one line of gear from doing its job: practice with the fitted gear (damage landed, ore cut, support cycles, deliveries, warps flown) builds a persisted counter. Each level gates advanced defs of that proficiency (fit a module, fly a hull) through the def's own level **and** authored prerequisite edges (for example artillery after autocannon II, destroyer after frigate II), and grants a small percent edge only while that proficiency is in use. Quality-weighted, never rolled: mining pays `2^(ore rarity-1)` (1/2/4/8), combat pays by applied damage (0.04 per point), a kill adds a caste bonus and a delivery pays by its authored level; the flown hull takes a share of every job act and the full kill/delivery credit, plus distance-based practice from completed warps. Five levels on sqrt pacing (`L = min(5, floor(sqrt(xp/10)))`), no wall clock, no RNG, no buyable shortcut, no decay and no accrual past V (the counter clamps at 250). Two cross-cutting lines (**Manufacturing** and **Refining**, both gate 0, no prerequisite) work on the industry and refinery paths instead of on fitted gear: a completed job pays its product's rarity and a completed 100-ore batch pays the ore's, and their edges are the material bill, the batch output and the refinery yield (see **Manufacturing proficiency** and **Refining proficiency**). Starter hulls and the world-start fit gate at 0; buying, selling and trading are never gated (own what you cannot yet run). Diegesis: the local, throughput-limited net carries manuals and bulletins, but knowledge bases never made personal skill obsolete, and there is no neural clone to buy hours into (the ban; death here is paperwork) |
| **Manufacturing proficiency** | the workshop proficiency for factory work (`content/proficiency.go` family `manufacturing`, label Manufacturing): a cross-cutting line, not a family of gear, so no def is gated on it and it carries no prerequisite edge (gate 0, like every gun line). Practice is the pilot's own completed job, paid at the **product's rarity** through the same `2^(rarity-1)` ladder mining uses (1/2/4/8), once per job whatever the run count; an agent-owned job pays nothing (agents have no proficiency and their behaviour is hashed). Card practice line: run manufacturing jobs. |
| **Manufacturing edge** | what a Manufacturing level buys, in two places: a job's material bill (`Sim.JobMaterials`) is 2% lighter per level and a batch recipe's output (`Sim.PlayerJobOutput`) is 2% larger per level, both capped at 10% at V (the level cap IS the clamp, so no extra bound is coded). The material reduction composes **additively** with the station's craft discount (`craftMatFactor(L) - 0.02·level`, so craft V's 8% plus Manufacturing V's 10% is 18% off a bill, not the 17.2% a multiplication gives). The output edge applies only where `RecipeDef.Qty > 1` and floors as the refinery floors: a hull or module job yields one unit at every level, ammunition yields 104 per run at II. Material factors are read at StartJob and the output at CollectJob, the same seam the craft factors use. An agent's bill never carries the pilot's edge (`Sim.jobBill` routes by owner). |
| **Refining proficiency** | the workshop proficiency for refinery work (`content/proficiency.go` family `refining`, label Refining): a cross-cutting line with no gate and no prerequisite. Practice is one completed whole batch of 100 ore, paid at the **ore's rarity** (1/2/4/8), once per batch; card practice line: refine batches at a station. |
| **Refining edge** | the Refining level's yield: `Sim.RefineOutput` is `floor(yield × qty × (1 + 0.02·level))` per mineral, capped at 10% at V. One function feeds both `execRefine` and the refinery's batch strip and picker, so the preview cannot promise a batch the command would not pay; at level 0 the multiplier is exactly 1 and every figure is the shipped one. The ore a batch eats never changes. |
| **Field note** | the pilot's own empirical knowledge of the world: one specific act observed once (first kill of a caste at a belt, a delivery landed, ore refined, a first trade at a station) records a **field note**, an instant chunk of a related edge or gate. Derived, never rolled, exactly like **Contact offer** (a pure function of state; the completed set is a sorted persisted list, so derivation moves no hash). Notes can also be **shared by contacts**, and by other future means. The word "research" never names it: no institution here does research (the fringe is never funded, never a quest-giver). Diegesis: the net's postings are not exhaustive and by no means complete, so what no bulletin carries is what the pilot saw |
| **Licence** | permission granted from standing: spend **standing** to open a hull class, module class or contact tier, and the corporate layer beside it: **patents and corporate secrets** under patent and copyright law, so some designs are faction-exclusive and reach the player only through their holder (EVE's faction-exclusive blueprints as the precedent, made available as content). Diegesis: the world already runs on paperwork ("licences renew, fines arrive by form"); a pilot may know how, the question is whether anyone is cleared |
| **Belief** | an agent's EWMA of executed trade prices (its market view) |
| **Haul wish** | an agent's cross-node arbitrage intent, flown as a real convoy |
| **Warp process** | align → accel → cruise → decel; spatial easing over a frozen timeline |
| **Departure beat** | the jittered 2–8 s hold a convoy keeps after spawning, resuming or arriving before it commences its warp, a stateless tick hash, never a persisted timer |
| **Gate cycle** | a stargate transit in two paced parts: the *dwell* (2–5 s at the gate before the hop) and the *jump cycle* (1–3 s between hop-out and materializing at the destination gate) |
| **Turnaround** | a station visit in stages: approach (2–4 s) → docked dwell (5–15 s, the cargo/market action fires partway through) → undock + departure beat |
| **Hold** | a shipment parked upstream of a full gate queue: it waits in the journey ledger until the far queue drains, logging one line on entering the hold and one when it finally jumps |
| **Contact** | a dock-side mission-giver representing a patron: the **Charter**, the **Commission** or a **corporation** (`contact-*`, `content/data/contacts/`); one station, one career-standing gate, and an offer pool whose live offers the sim derives from world state (a front's supply gap, a station's requisition shortfall, rats working a system). "Agent" stays the ledger layer and never names a mission-giver |
| **Contact offer** | one authored offer (`offer-*`) of a contact's pool: a `deliver`/`kill`/`mine` task whose parameters (count, station, system, caste) the sim fills from its own state, and whose prose carries the same slots (`{count}`, `{system}`, `{station}`, `{caste}`, `{item}`, `{urgency}`). Nothing is persisted before accept: offers are re-derived every evaluation, so a closed gap simply stops producing its offer |
| **Requisition stock** | a station's resting sell orders for an item: what its guard posts buy replacements from. A completed delivery lands its cargo on the destination's book as a sell order, so delivered materiel becomes stock the posts actually draw from |
| **Agent cooldown** | per-agent jittered 1–10 s between behavior acts; one act moves capital at most once (its job / quotes / wish slot rotates on a stateless tick hash) |
| **Belt sweep** | the security response to pirate rats parked on a Charter-space (high-sec) belt: a static guard clears the rats anchored at its own celestial, and a traffic patrol sweeps an occupied belt once per **patrol beat** (the authored patrol cadence, re-armed after every sweep) and flies home. A sweep stays until the belt is empty and hunts stragglers off the anchor; free rats are engaged first, and a fight a pilot is already in is theirs only while another rat is free. The Fringe / Unincorporated get no sweep. The last rat of a belt dying logs one `<belt> cleared` line; the belt's respawn timers re-arm it. Every high-sec station carries a four-cutter static post (Rydnok's belt too; the Struvok belt is the one authored exception: no post, held by the station's cutters, the response wing and the sweep), and a high-sec patrol schedule comes round every minute |
| **Hostility** | who may initiate on whom: [lore/FACTIONS.md](docs/lore/FACTIONS.md)'s Relations table as code (`sim/hostility.go`, faction string → the factions it may act against). Only the Old Works are hostile (everything non-Old-Works: traffic, miners, you) and the Charter answers them; corporate houses, independents and unknown factions initiate nothing (fail closed), and same-faction pairs are never hostile. Role passivity stacks on top: guards never initiate (self-defense, the high-sec belt rule and the **outlaw** warrant aside), miners never initiate. They do flee when damage takes their structure under the temperament threshold. High-sec security is overwhelming: the Kuštor carries three medium autocannons and ~2000 EHP, a response wing is ten cutters, and a high-sec post leaves no belt unguarded. Security also answers miner distress: a Dvužek barge hit in charter space draws the same wing, held on the barge and the rats around it (one live response per miner, none inside Works control; see **patrol response**). The threat machine (`sim/systemNpc`) is a **behaviour tree** over the player, AI hulls and traffic haulers alike: one candidate-based rule set, so a mining op that draws a rat draws it the same way your lasers do (shipped content with a faction and no relations row fails a test); among the candidates it triggers, **prey preference** ranks the engagement and a **threat switch** re-targets a fight already under way |
| **Behaviour tree** | how an NPC role decides one tick: one tree of named rule leaves (`sim/btree.go`, `sim/system_npc.go`: `aggressiveTree`, `guardTree`, `minerTree`, `patrolTree`, `raiderTree`) evaluated by `Sequence`/`Selector` in declaration order. Stateless: no clock, no goroutine, no RNG, no per-tick allocation; a leaf reads world state and writes the decision, and `NpcAI.State`/`Target` plus the tick's `Intent` are the only memory, so the tree is re-evaluated from scratch every tick and survives save/restore through the NPC state it produces. Motion (patrol circles, approach/orbit, flee, warp) stays in the routines the leaves call; traffic leg scheduling and war episode timelines are not trees |
| **Prey preference** | which triggered candidate an aggressive NPC engages: the damage source first (initial aggro), else the highest prey score `0.5·(carry/max carry) + 0.5·(guns/max guns)` over the eligible set; carry = cargo capacity + ore hold, guns = fitted weapon modules, maxima set-relative, equal weights. Equal scores go to the nearer candidate, then canonical handle order. Guards rank the rats they clear the same way; raiders and patrols keep the incident's assignment |
| **Threat switch** | when an engaged NPC changes target: another hostile's damage over the trailing 120 ticks must be ≥ 2× the current target's over the same window (`npcSwitchLead`) and 600 ticks must have passed since the last acquisition or switch (`npcSwitchDwell`); the window then restarts and the hull re-enters approach. A wing-mate of the current target never triggers it, a hull with no live target still answers any attacker immediately, and the same rule gates the engaged-idle guard/raider flip. The damage window and dwell marker are transient (`NpcAI.HitLog`/`SwitchAt`: not saved, so a restore starts the window empty, like the player-work marker) |
| **Patrol response** | the Charter's answer to an incident, dispatched by `trafficRespond` with a `trafficPatrolWing(σ)` wing (ten high, one low, none null) at a convoy ambush or, as the second incident kind, a miner under fire (`minerDistress`: any hostile hit, one live wing per miner, never inside Works control, delayed in low space by holding the wing at the anchor). `Patrol.Aggressor` records the hull reported to have opened fire, so `patrolMinerStep` holds station on the barge and clears that aggressor first (a pilot who shot the barge) and the rats around it within the ambush engagement range; responders never initiate on an innocent pilot |
| **Friendly fire** | the confirmation between a pilot and a peaceful hull: an aggressive module (`ModuleDef.IsAggressive`: weapons, stasis webs, warp scramblers) aimed at a crewed ship that is not at war with independents and not already fighting back does nothing until the player confirms it. The sim refuses the activation and emits `EvFriendlyFire` with the slot, the target and the module; the client opens one dialog naming all three, whose **Confirm foolishness** re-sends the same command with `Confirm` set (Cancel and × send nothing, and a refusal records nothing). Rats, raiders and unpiloted hulls never ask: `peacefulShip` is the gate's one predicate |
| **Target class** | what a module's activation takes as a target (`content.ModuleDef.TargetClass`: ship, any locked entity, asteroid, or self): the one answer the sim's activation gate enforces and the rack's click-pick reads (`TargetClass.Suits` over the view's ship/asteroid reads), so a new kind edits one table instead of a UI copy that can disagree |
| **Outlaw** | the warrant that follows persistent friendly fire: the first confirmed act opens a run, every later friendly-fire hit slides a 60 s window (`aggressionWindowSec`), and once the run spans 10 s (`aggressionPersistSec`) every security hull treats the pilot as a valid target on sight, through the ordinary threat machine (guard posts by their authored aggro range, standing patrols, response wings and belt sweeps by the ambush engagement range). One `EvOutlaw` announces it; the warrant lapses after 60 s without an act. Transient like the **threat switch**: it never enters the Save, so a restore starts clean |
| **The Long Attrition** | the war of the Wild Fields: corporate fleets under the Commission fight the Old Works for territory; charter ⇄ unchartered flips are its scoreboard, the contest meters its pulse, and the economy feeds it. Rare flips, always on, from tick 0 |
| **War** | the sim's war state (`sim.WarState`, one additive `Save` field): per-system **control** (`charter`/`works`, seeded from the authored security tier: `high`/`low` → charter, `null` → works), the front's **contest** meters, and the **war treasury**; ticks with the sim, never wall-clock |
| **Effective security** | what a flip leaves behind: control-derived security that re-derives every behavior the authored tier used to drive (guards, patrols, temperament, ambush rates, sweeps). Fall → `null`; reclaim → the authored tier returns |
| **Front** | the contiguous boundary where charter and works control meet across gates; every system on it carries a contest meter, and the war moves only here |
| **Contest** | a front system's charter-vs-works meter: pushed by **supply** (procurement credited to it, plus kill attrition) and eroded by **works pressure** scaled by the squeeze curve; crossing the threshold flips the system, rare by construction |
| **Squeeze curve** | the Works' exponential resistance as their territory shrinks: one global curve off works share, acting on the meter pushback AND the grid (spawn mix shifts toward tougher castes). The Works can be cornered but never extinguished: the war never ends |
| **Procurement** | the war's standing demand: treasury-funded buy orders on every charter-held book for everything military. Fills pay the seller at once (your earnings), consume the goods (the sink), and credit supply to the nearest front after an abstract haul delay; NPC haul convoys cart war goods toward the front wherever you are to see it |
| **War treasury** | the Corporate Fleets' ledger, seeded like a faction ledger and refilled by the **fee cut**, a share of broker fees and sales tax rerouted instead of burned. Its balance is war health; the war mints nothing, and starve the economy and the charter loses |
| **Remnant** | a station after its system falls: market and repair stay live (lawless), charter services (contracts, industry, fitting) go dark, guards leave, and the Works take the belts, never the docking ring. Reclaim restores the authored set |
| **Corporate Fleets** | the bloc faction behind the commissioned fleets: hostile to the Old Works only, neutral to everyone else unless provoked. One row now; per-corp rows may grow later when a corp needs its name on screen |
| **The Svaz** | the weak confederation binding the cantons and the corporations, heart in the old worlds, a dues line and a warrant at the rim: treaty, dues, the Commission. Institutional only: no office, no officer and no answer in the Wild Fields. "The empire" in prose |
| **The Commission** | the Svaz's war commission: the mandate under which corps raise and crew fleets. The Charter stays army-less: its law is insurance, not war |
| **Predecessors** | the civilisation before the settlement waves: it built the Old Works and lost the oversight, and why is not preserved. Known through oral tradition, a scholarly fringe and the machines themselves; never a witness, an archive or a name of its own |
| **the Kanžar Inspectorate** | the Svaz's ban on machine minds and autonomous self-replicating systems, in institutional form: a name on a form. Offstage by canon: no office, no officer, no hull, no sim state, never a screen |
| **Legacy id** | a content id a rename retired, mapped onto its replacement in `content.LegacyIDs` (the keys are `content.RetiredIDs`): validation rejects them in shipped content, and restore remaps them in place; `sim.walkContentIDs` finds every id a save carries by reflection, so a new id-bearing field needs no second list |

## Architecture (the UI tranche)

| Term | Meaning |
|---|---|
| **Screen** | a window the player can open: declared as one **Screen spec** row (id, the frozen layout-sidecar key, title, icon, key, default rect, dock policy, modal facet, build) whose built **Screen panel** the **Screen host** mounts, syncs, dismisses and places. The layout sidecar, the frame sync, the × close and the title-bar name all read the host (that name is the row's static display name; a title bar carries no live state); a transient row keeps its id but no sidecar entry |
| **Screen host** | the Game-free state machine between Screen rows and their panels (`game/screenhost.go`): one instance for the game table, one for the title's own table (a title host's rows follow their flags: its table IS the title set). It owns the open flag, the mount (spec order), the mount-frame Sync, the committed-close dismissal, the layout entry, the placement tracker, a **Modal row**'s whole step (open and close, the veil, the Esc order, a session's return) and a **Persistent panel**'s visibility (the room's rule AND the flag, resolved as a hide); **Rebind** drops the panels with a rebuilt kit and keeps the open flags and any session |
| **Screen panel** | a Screen row's built product: a `widgets.WindowPanel` (window + Sync). Optional capabilities are asked by type: `Splits()`/`Tables()` for layout persistence, `Dismissed()` for the committed × close, `Unmounted()` for teardown, `FitSize()` for a content-hugging window (the **Fitted** facet: the host mirrors the **Station board**'s floor onto MinSize and composes its declared column through the placement tracker), so a window persists or hooks by implementing the facet, never by appearing in a name switch |
| **Interface rebuild** | the one lifecycle that rebuilds the whole interface against the current sim (`Game.rebuildUI`, declared by a `uiRebuild` value). It survives: the event log, the **Screen host**'s open flags and sessions, the placement (round-tripped through the design-unit sidecar when the scale moves) and the title host (rebound to the fresh kit like the game host). It resets: the selection (a fresh kit starts it empty) and the space camera, which only a caller declares. Order: capture the log, install the scale, build the kit and its defaults, mount through the host, rebind the title host, restore the log and the saved layout, recentre. The four callers differ only in the declared value: boot (nothing), load (saved layout and recentre), a scale change (placement round trip), a settings reset (the scale change back to 1×). A build failure returns one error for the caller to report once, and the previous kit stays live |
| **Modal row** | Screen row facet every modal window declares (`Screen.Modal`: `Dim` veil alpha, `Pauses`, `Session`). The **Screen host** owns the whole step: the row's one toggle opens and closes it (key, rail, ×, menu button), the host paints its veil between the scene stack and the kit in declaration order, and Esc closes it. `Dim` IS the modality (a row with no veil is an ordinary window); `Pauses` is the pause layer, which owns the key layer while up (the Esc menu, and the session it opens); `Session` names the row this row is a session OF: opened while that row is up it replaces it as a modal, dimmed layer, and closing hands back to it, while its own key still opens the plain window (the Settings window from the Esc menu). Esc is one ladder and no window owns a scene: the **Proficiency card**, then the tree layer, then the open modal rows in reverse declaration order (the menu, declared last, outranks help), then the menu opens. |
| **Persistent panel** | the Screen row facet the two always-on windows carry (the Overview and the Selected Item window, `Screen.Persistent`): the kit builds the panel (`uikit.Kit.OverviewPanel`/`SelectedPanel`: construction, the selection wiring and the overview's table), and the host does everything else every other row gets: the mount, the placement, the sidecar entry, the × close handshake and the visibility. Its open flag is the player's close and the room's rule only HIDES it (the window stays mounted, so a close, a dock or a rail re-show never loses its rect, stack slot or table state), which is what replaced the kit's own `coreShown`/`coreClosed` pair. The landing is the corner (`AnchorTopRight` for the overview, `AnchorTopLeft` for Selected Item) and the sidecar keys are `overview` and `selected`, the retired core layout's own, so an older save's sidecar restores unchanged; Show Info keeps the one geometry-only sidecar row (`infowin`) |
| **Board scaffold** | the three-pane boards' shared frame (`uikit/screens/board.go`): the **Browse column** over the list and content panes (two draggable seams, opening shares per window), and the content pane itself: the **Item head**, one scroll column with the **Scroll gutter**'s rail, the pinned action bar and the measured inner width. It is a value, not a window: each board supplies its page model (a comparable struct), its rows, its verb and its opening shares, and the pane rebuilds only when that model moves, so every displayed input has to be in the model (the **Station board**'s rule). The two inspectors pin the head above the page; the market's right pane carries it inside the page. The **Board search** machinery is shared while the policy is not: the boards keep their substring gate and the market keeps its highlighted, ungated rank |
| **Browse column** | a board's left pane: the live search field over the group tree (`browseTree`, `panes.go`), scoped branch and highlighted row, built once for the market, the recipe board and the refinery |
| **Board search** | the boards' one ranked search (`boardSearch`): fold the query and every field (`fold.go`), optionally require one field to contain the query, rank by `sahilm/fuzzy` and return the keys (with the matched rune starts when the caller draws the highlight). The boards keep the gate (a subsequence scattered across two fields is not a hit; a mineral query finds the recipes that eat it and the ores that yield it), the market does not and highlights instead |

One instance per session, mounted by the Kit on first open (`Kit.OpenQty`), seeded with the surface's last **confirmed** value (clamped to the live range; a rebuilt interface starts at 1); Esc cancels it before any window close, Confirm/Cancel close it, and a cancelled picker writes no intent and no memory |
| **Transfer popup** | the inventory's drag-and-drop move, and the **Quantity picker**'s transfer face: pressing a stack (a table row or a tile) arms a drag whose ghost chip (the item's icon and name, palette chrome) follows the pointer, releasing over ANOTHER hold's section opens the picker with the item's mark, its name, the destination (`→ Station hangar`) and a slider over 1..that stack, defaulting to the whole stack; Confirm emits the same `Transfer` intent as ever, so the sim's capacity gate and refusal wording stay the engine's (no client cap). A release on the same hold or empty space is a no-op, and so is a drop on the undocked hangar; the hovered target section wears an accent frame. The toolbar's To Cargo/To Ore/To Hangar buttons are gone (Sell, row menu verbs and the Show Info gestures are not moves and stay). Session-only: it persists nothing |
| **View mode** | the inventory's two-state view toggle (`List`/`Tiles`, the title bar's icon button beside the ×, session-only like the market's folded sections, because the layout sidecar persists geometry and never view choices): **list** is the three Item/Qty/m³ tables, **tiles** swaps every section at once for a wrapped grid of square item tiles (the fitting/rack icon box at `theme.IconTile`, the item's name and `×N` count beneath), flowing to the pane width through the house scroll rail. One title-bar icon button names the view it switches TO (`cubes` for tiles, `row_module` for the list, the manifest's nearest row glyph; no new art) and its tooltip carries the word. Each hold's header carries its **fullness bar** instead of the old used/capacity text: the HUD's `widgets.ValueBar` (progress bar under the centred figures), filled used/capacity clamped, hidden when the hull has no such hold; the hangar is unlimited and keeps its stack-count label with no bar |
| **Ticker box** | `widgets.CheckBox` (the owner's word for a checkbox): a 16 px marker beside its label on one clickable row, flipping on a press edge and reporting through `OnChange`; the marker is a Border-edged Cell square with the context menu's two-stroke Accent tick (palette only, no new colour), lit while hovered. Input is the Slider's discipline (the panel polls the pointer frame from Sync, the press must land on the widget's own active input layer) and `SetChecked` is the silent host mirror. It is the overview filter window's Show/Colour switch, the first roster entry for a tick |
| **Overview filter** | the overview's per-kind list state (`uikit/screens.OvFilter`): one **Show** and one **Colour** tick per kind, opened by the cog in the overview's title bar (no key, no rail row, one Dialog instance). Only deviations are stored (a kind absent is shown and coloured), so a default state writes no sidecar bytes; it rides the layout sidecar's overview row through the optional `filterEntry` facet. The filter touches the list alone (world, selection and locks stay), the pilot's own `KindPlayer` row has no switch and is never hidden, and the `Ship` switch governs `KindShip` only. Colour off zeroes the row and icon tint; today only the pilot and hostiles carry one, so the other kinds are forward-compatible no-ops |

| **Dialog** | one on-demand Kit window's lifecycle (`uikit/screens/kitdialog.go`, **Kit-internal**: unexported, no new public surface): its `win`, the panel's `hide`/`isOpen` closures, an optional `place` hook and the live mount handle. One `newDialog` registers the window's `×` (`SetWindowClose`); one `showDialog` absorbs the launch rules: re-target first (a refusal mounts nothing), then `place`, then remove + re-add on top with `animate = false` when already open, and a launch during a close fade drops the pending unmount and fades back in; `closeDialog` is idempotent (unmount, hide). Show Info, the order mini-window, the quantity picker, the overview filter window and the contact details page are its five instances; only the picker sets `place` (it centres on every show; the others never jump on a re-target). `addWindow`'s fade/settle/stack rules, `raise`, `Over` and the panels' own `Show` stay out; the shared `Close`/`hide`/`IsOpen` trio (with a per-panel hide hook) is `dialogShell`, embedded by every panel |
| **Column prefs** | a table's per-column state (`widgets.ColumnPref`): the width and hidden flag the player sets through the header's **grips** (6 design-px strip at each column's right edge, its own blocking input layer, EW cursor) and the **⋯ column menu** (flat, one ticked row per column, last visible column disabled). Two policies: the **first fit** measures the content once and freezes each column's base, later content changes ellipsize, never move an anchor; **every later layout** (table resize, hide/show, stored prefs) distributes the table width over the bases **proportionally**, so a player-made width persists, a hidden column restores its base and a grip drag or table resize re-bases at the widths on screen. Every table tags itself with a sidecar id (`widgets.PrefsID`); widths and hidden flags ride the layout sidecar's `tables` map in design units |
| **Target card** | one locked target's readout in the HUD's top-centre row: the kind glyph and name, the distance, the lock strip, the layer bars and miniature rack cells of the player's own modules cycling on it (`sim.ModuleTarget`: the class glyph plus a depleting cycle ring, the rack's active/pending/loading states, three a card). A left click on it is the same selection as a world click (`Kit.Select`), never a lock, never a camera move. A card whose target is gone (destroyed, warped off, unlocked) hangs on as a **ghost** for 1.5 s, alternating visibility every 15 frames (2 cycles a second, frame-counted), then drops; a ghost answers no click |
| **Combat feed** | the HUD's brief line feed above the ship status: one line per player-relevant combat event, the important span red when it lands on the player (`Danger`) and blue when the player lands it (`Info`). It reads the sim's structured `EvCombat` (damage with source, victim and amount; web and scramble on a fresh application) and the kill events, keeps `hudFeedLines` (4) lines alive for 5 sim seconds each, and is an **overlay**: TOP chrome (`Kit.AddTopContainer`) that paints over windows and takes no room from the HUD's bottom column |
| **Effect box** | the HUD's live-effect readout directly above the ship status: one rack-cell-miniature per effect on the player, its class glyph, a depleting cycle ring and the seconds left read from the sim's expiry (`Motion.WebbedUntil`, `ShipState.ScrambledUntil`), shown only while that expiry is ahead. Today the two EWAR effects `content/data/modules/ewar.json` ships (stasis web, warp scramble); no other effect gets an icon |
| **Entity label** | the world's one name/distance label: drawn for the entity under the cursor and nothing else (`Renderer.SetHover`, resolved by the scene's `pick` every update; zoom plays no part). Brackets alone identify what is out there, and the cursor asks one name. A locked target's label is hover-only too (the Overview carries its figure) |
| **ContentView** | the read-only seam: defs + observable sim state as screens see it, implemented over `*content.Content` + `*sim.Sim`; screens never see the simulation. One member per domain read, not one per query: `Market()` (`MarketView`: docked book, system orders, quote walk, cheapest ask, displayed ladder), `Industry()` (`IndustryView`: jobs and the per-recipe materials, fee, gate, duration, output, refine), `Holds()` (`HoldsView`: the two holds and one hold's volumes), `Hangar()`, `Contacts()`, `War()`, then the single reads no domain owns (state, component snapshots, the info refs, finance) |
| **ActionSink** | the write seam: screens emit typed **intents** (`Buy{Item,Qty}`, `StartJob{…}`, `QtyPick{…}`) through `Do(Intent)`; the game executes them (`Game.Do`); later the AI surface will emit the same ones |
| **World verb** | one row per in-space command (`uikit/screens/worldverbs.go`): `Action` (the frozen `worldKeyMap` id, the row's only name; a surface that speaks a verb carries its own wording, e.g. the Selected Item caption), `Rule` (`TargetSelected`, `TargetSelectedElseNearest`, `TargetNearest`, `TargetCycle`, `TargetSelf`), `Eligible` (may act at all: the key path, the panel and the nearest-fallback filter), `Ready` (the panel's disabled state and why text only; a sim refusal stays the key path's feedback) and a pure `Emit` that builds a `widgets.Intent`: never a command, `commandFor` stays the only intent→command table. The key path (`Game.worldKey`), the Selected Item buttons and the overview row actions all resolve through these rows, and the AI surface emits the same intents (the ActionSink promise). The Selected Item panel's buttons are one declared slice (`selectedPanel.verbs`): build appends a row per verb and `syncSelected` gates that same slice, so a button cannot exist without its gate |
| **Seams** | the union `Theme` + `ContentView` + `ActionSink` plus the host's **Pointer frame**: the constructor param of a screen that draws, reads *and* acts (`uikit/widgets.Seams`; the dissolved `Env` is only this alias) |
| **Pointer frame** | one frame's gesture (`uikit/widgets.Pointer`): ONE sample of the pointer per Update (`Begin`, the host's first line; position, held buttons, press edges) that every widget reads instead of the OS, so the world and the interface hit-test the same point. `Press` is the frame's edge unless the frame **spent** it (`Spend`, the context menu's Click/Esc own the gesture), `RawPress` is the edge always (Menu.Poll's own read: the popup acts on the press that dismisses it), `Down` is the held state. It also owns the frame's **shape**: claimers only declare (`ClaimShape`, last claim wins: the chrome steps after the pane polls, so a grip outranks a seam) and `Apply` (the host's end of Draw) writes the winner once, never re-sampling, so ebiten's draw-only frames repeat the last decision instead of falling back to the arrow. Widgets keep what a gesture *means* (a seam grab, a column drag, a menu dismissal); the frame only says what the pointer *is*. One per host, owned by the `Game` (`Options.Pointer`, survives a kit rebuild), reached by every panel through `Seams.Pointer`; a `Source` supplies the sample (`OSInput` in production, a script in tests) |
| **Hit test** | one press-ownership walk (`uikit/screens/hittest.go`): `Kit.Own(pt)` answers where a point lands (`Owner{Layer, Window, Control}` over `World`, `Popup`, `TopChrome`, `Window`, `RootChrome`, `Hovered`) in exactly this precedence: the popup latch (`Kit.Held`, set by `MenuInput`/the picker's poll, Control sampled before the poll so the press that runs an entry still counts), the popup's own rect (`MenuRect`), a visible **modal** window (its input layer is fullscreen, so nothing below it is owned), the top chrome (the rail and the HUD's target-card row), the window stack topmost first (its widget walk, then the window's registered row surface, `SetWindowRows`, one live closure per mount, since a table's rows sit in a scroll viewport the walk cannot descend into), the root chrome's **descendants only** (the HUD container stretches over the whole screen and owns nothing by itself), and last ebitenui's hover flag, which gates but never raises. Every consumer reads it and nothing else: `Over` = layer ≠ World (the host's world gate), `PressTarget` = `Control` (the click cue), `raisePressed` = a press edge whose owner is a window that is not the stack top. `Popup.Control` is true for the popup's entries (and the picker's controls) only: a press that just dismisses the popup stays silent |
| **Session** | one host's environment: the three seams plus its pointer frame and its shared context menu, Show Info window and quantity picker (`uikit/screens.Session`, from `Kit.Env` / `NewEnv`) |
| **uikit modules** | `uikit/theme` (visual constants + the Theme seam) ← `uikit/widgets` (mechanics: table, menu, tooltip, rowspec, intents, seams) ← `uikit/screens` (the panels + Kit): each layer imports only downward, pinned by `TestImportDirection` |
| **Deep module** | a module whose interface is small and whose implementation absorbs complexity (the goal of every seam here) |
| **Close button** | the `×` affordance at a title bar's right edge: registered per window through `Kit.SetWindowClose`, wired to that window's existing close semantics (Screen-row toggle, core toggle, Show Info close). Its hit strip is excluded from the chrome-owned title drag; the window's resize grip keeps precedence where the strip meets a grip band |
| **Window animation** | the render-only open/close fade: a mount fades + slides in over 12 frames, a close-button close fades out over 10 frames before its unmount runs. The animating window is parked out of ebitenui's window pass and composited through one offscreen with alpha/translate: input is live throughout the open fade, inert throughout the close fade; no rects, layout or simulation state move |
| **Settle** | an animation completing: an open window snaps to the normal paint path, a closing window runs its deferred unmount. A raise settles every animation (nothing may fade below a retopped window); a new open mount settles the close fades only (the other open fades below it keep running; the composite walks the stack in paint order); a drag-arming press settles that window's open fade, so a fade's park flips can never relayout a subtree a drag is translating |

## The stat language (icons + families)

| Term | Meaning |
|---|---|
| **Stat family** | the hue a stat row is tinted by, one per kind of number: **Offence** (crimson), **Defence** (shield blue), **Capacitor** (green), **Mobility** (teal), **Utility** (info blue), **Mining** (amber), **Economy** (good green), **Fitting** (structure silver). Six owned hues in `theme.Palette` (`StatOffence`…`StatExplosive`) and six reused chrome roles; identity rows (Class, Maker, Origin, Family, Faction, Hull, Kind, Category, Qty) carry no glyph and no tint |
| **Damage sub-system** | the damage types are their own four families behind the eight (**EM** violet, **Thermal** red, **Kinetic** yellow, **Explosive** orange), one glyph per type serving its damage row, its EHP row and its resist row |
| **Stat table** | the one census (`uikit/theme/stat.go`): label → glyph + family, plus the section-bar map. Every renderer (info page rows and section bars, tooltip rows, the fitting window's stat rows and hull limits, stat-mapped table headers, HUD bar glyphs) reads it, so a new stat lights up on every surface or fails `TestStatTaxonomyCoversCensus` |
| **Paired info line** | the ship and module pages' stat layout: a section's rows sit on explicit lines of one to three equal cells (single rows are full-width), so related figures share a line and long or dynamic rows span it |

## Vocabulary rules

- Display names follow `docs/lore/NAMING.md`; ids (`sys-*`, `mod-*`, …) are frozen artifacts (the one exception is an owner-ordered rename, which lands in `content.LegacyIDs` with its retired ids rejected by validation and remapped in old saves).
- Money renders trailing-euro (`12,345.67 €`, `50¢`); zones are Charter space / the Fringe / Unincorporated.
- New concepts get named here before they get built.
